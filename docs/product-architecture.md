# e-hub 产品与权限方案

## 产品边界

e-hub 分为门户网站和运营平台，两者在品牌上统一，但产品边界分开。

门户网站面向外部访客、合作方和潜在客户，主要承载产品介绍、能力展示、接入合作和登录入口。

运营平台面向内部运营人员和客户，承载登录后的业务操作、数据查询和权限管理。

## 平台分层

```text
e-hub
├─ 门户网站
│  ├─ 首页
│  ├─ 产品能力
│  │  ├─ 负荷聚合
│  │  └─ 电价能力
│  ├─ 接入合作
│  └─ 登录入口
└─ 运营平台
   ├─ 我的运营平台
   │  ├─ 工作台
   │  ├─ 客户管理
   │  ├─ 用户管理
   │  ├─ 产品开通
   │  ├─ 权限管理
   │  └─ 系统设置
   └─ 客户运营平台
      ├─ 负荷聚合
      │  ├─ 运营总览
      │  ├─ 历史查询
      │  └─ 设备/资源数据
      └─ 电价能力
         ├─ 全国电价查询
         ├─ 接口能力
         └─ 调用记录
```

## 当前产品能力

当前核心产品能力有两个：

- 负荷聚合：当前已有总览看板、历史查询、收益结算、调节情况、出清价格等能力。
- 电价能力：后续提供全国电价查询展示、接口能力和调用记录。

设备管理数据归属于负荷聚合里的设备/资源数据，不作为客户运营平台的独立一级产品。

## 权限模型

运营平台菜单不应写死，应由登录用户的平台类型、产品开通状态和权限点共同决定。

核心字段：

```js
{
  platformType: "owner" | "customer",
  tenantId: "customer_a",
  role: "customer_admin",
  products: ["load_aggregation", "tariff"],
  permissions: [
    "load:overview:view",
    "load:history:view",
    "tariff:query:view"
  ]
}
```

规则：

- `platformType=owner`：进入“我的运营平台”，展示客户管理、用户管理、产品开通、权限管理、系统设置等内部运营能力。
- `platformType=customer`：进入“客户运营平台”，只展示客户已开通的产品能力。
- 开通负荷聚合的客户只能使用负荷聚合相关页面。
- 开通电价能力的客户只能使用电价查询、接口能力、调用记录等页面。
- 同时开通多个产品时，菜单展示多个产品域。

## 当前代码改造目标

当前项目先定位为运营平台，不承载门户网站。

本阶段前端先使用 mock 用户权限驱动菜单，后续替换为登录接口或权限接口返回值即可。
